## 1. Цель работы

Освоение асинхронных операций в браузере: подключение готового HTTP API к пользовательскому интерфейсу. Получение навыков управления состояниями загрузки (`loading`, `ready`, `empty`, `error`), безопасного вывода данных через DOM и защиты интерфейса от устаревших ответов при помощи `AbortController`.

## 3. Реализация

### 3.1. HTTP-клиент

Клиент поддерживает методы `GET`, `POST`, `PATCH`, `DELETE`. Для запросов с телом (`POST`, `PATCH`) объект автоматически сериализуется через `JSON.stringify` и добавляется заголовок `Content-Type: application/json`. Если сервер возвращает статус `204 No Content` (при DELETE), клиент корректно возвращает `null`, не пытаясь вызвать `response.json()`.

### 3.2. Доменный API

Файл `task-api.js` инкапсулирует маршруты и схемы данных. Схема ответа проверяется после каждого запроса (валидация типов полей, уникальности `id`, соответствия `meta.total`). Для мутаций используются методы `createTask`, `updateTask`, `setTaskCompleted`, `deleteTask`.

### 3.3. Состояния интерфейса

Контроллер управляет 4 состояниями:

- `loading` — при первичной загрузке или смене фильтра.
- `ready` — список задач получен и отрисован.
- `empty` — сервер вернул пустой массив (нет задач по фильтру).
- `error` — при сетевой ошибке или 500-й ошибке сервера, показывается кнопка «Повторить загрузку».

### 3.4. Изменение данных

Используется пессимистичный подход. При отправке формы или нажатии кнопки удаления/смены статуса, интерфейс блокируется (`setMutationPending`), выполняется запрос к API, а затем список задач перезапрашивается заново (`GET /tasks` с текущими фильтрами). Это гарантирует, что интерфейс показывает только те данные, которые реально сохранились на сервере.

### 3.5. Защита от устаревшего ответа

Если пользователь быстро меняет фильтры, предыдущий запрос отменяется через `abortController.abort()`. Кроме того, каждому запросу присваивается уникальный `loadId`. Если ответ пришел от старого запроса, он игнорируется (проверка `currentLoadId !== loadId`).

**Начальный фильтр:** `{ categoryId: 2 }`<br>
